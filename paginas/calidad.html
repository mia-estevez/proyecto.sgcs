Gestión de la calidad del software

¿Qué es la calidad del software?

La calidad del software se refiere al grado en que un sistema cumple con los requisitos definidos y satisface las necesidades de los usuarios, además de presentar características que permitan que sea confiable, seguro, mantenible y fácil de utilizar.

No se trata solamente de que el programa funcione. Un software puede cumplir su función principal y, aun así, presentar problemas relacionados con el rendimiento, la seguridad, la facilidad de uso o el mantenimiento.

Por este motivo, la calidad debe considerarse durante todo el proceso de desarrollo, desde la definición de los requisitos hasta la evaluación y mantenimiento del producto.

01 — FUNDAMENTOS

Fundamentos de calidad

Las normas y modelos de calidad permiten analizar diferentes aspectos de un producto de software. De esta manera, la calidad no se evalúa solamente por si el programa funciona, sino también por cómo funciona, qué tan fácil es utilizarlo y mantenerlo, entre otros aspectos.

¿Qué es la ISO/IEC 9126?

La ISO/IEC 9126 fue una norma internacional utilizada para establecer un modelo de calidad de los productos de software. Su objetivo era proporcionar características que permitieran evaluar y describir la calidad de un producto de manera organizada.

El modelo dividía la calidad del software en seis características principales. Cada una permitía analizar un aspecto diferente del producto.

Características principales

Funcionalidad

Evalúa si el software proporciona las funciones necesarias para cumplir con los requisitos y necesidades de los usuarios.

Fiabilidad

Se relaciona con la capacidad del sistema para mantener un funcionamiento correcto y estable durante un período determinado.

Usabilidad

Considera qué tan fácil resulta para los usuarios comprender, aprender y utilizar el software.

Eficiencia

Analiza el rendimiento del sistema y la cantidad de recursos que utiliza para realizar sus funciones.

Mantenibilidad

Evalúa qué tan fácil es analizar, corregir, modificar o actualizar el software.

Portabilidad

Se refiere a la facilidad con la que el software puede trasladarse y adaptarse a diferentes entornos o plataformas.

Importancia

La ISO/IEC 9126 permitió contar con una referencia común para describir y evaluar la calidad del software. Actualmente es considerada una norma histórica y su modelo fue reemplazado por la evolución de la familia SQuaRE.

¿Qué es ISO/IEC 25000?

ISO/IEC 25000 forma parte de la familia SQuaRE (Systems and software Quality Requirements and Evaluation). Esta familia reúne normas relacionadas con los requisitos, modelos, medición y evaluación de la calidad de productos de software.

Su objetivo es proporcionar una estructura para especificar los requisitos de calidad y poder medir y evaluar diferentes aspectos de un producto de software.

Modelo de calidad

Dentro de la familia SQuaRE se encuentra ISO/IEC 25010, que define un modelo para evaluar la calidad de los productos de software. La versión actual del modelo contempla nueve características.

Características de calidad

Adecuación funcional

Evalúa si el sistema proporciona las funciones necesarias para satisfacer las necesidades especificadas.

Eficiencia de desempeño

Analiza el rendimiento del sistema en relación con los recursos que utiliza, como tiempo y memoria.

Compatibilidad

Evalúa la capacidad del software para funcionar junto con otros sistemas y compartir información.

Capacidad de interacción

Se relaciona con la facilidad con la que los usuarios pueden interactuar con el sistema de forma efectiva.

Fiabilidad

Considera la capacidad del sistema para mantener un funcionamiento correcto bajo determinadas condiciones.

Seguridad

Analiza la capacidad del sistema para proteger la información y controlar el acceso a los datos y funciones.

Mantenibilidad

Evalúa la facilidad para analizar, modificar, corregir y mantener el software.

Flexibilidad

Se refiere a la capacidad del software para adaptarse a cambios en diferentes contextos y necesidades.

Protección

Considera la capacidad del sistema para evitar situaciones que puedan provocar daños a personas, bienes o al entorno.

Importancia

La familia SQuaRE permite utilizar criterios organizados para especificar, medir y evaluar la calidad de los productos de software, facilitando una evaluación más completa del sistema.

Métricas de la calidad

Una métrica de software es una medida que permite obtener información objetiva sobre algún aspecto del software o de su desarrollo.

Por ejemplo:

  • Cantidad de errores encontrados.
  • Cantidad de errores corregidos.
  • Porcentaje de pruebas exitosas.
  • Cobertura de pruebas.
  • Tiempo promedio para corregir un defecto.
  • Cantidad de defectos por tamaño del software.
  • Tiempo de respuesta.
  • Disponibilidad del sistema.

Ejemplo

Supongamos que tenemos:

  • 100 casos de prueba.
  • 90 fueron exitosos.
  • 10 fallaron.

Podemos calcular:

Porcentaje de pruebas exitosas = 90 / 100 × 100 = 90 %

Esto nos permite tener una medida objetiva del estado de las pruebas.

Las métricas son importantes porque permiten medir, comparar y detectar problemas, en lugar de basarnos solamente en opiniones.

La familia ISO/IEC 25000 contempla específicamente una división dedicada a la medición de calidad, con modelos de medición y definiciones de medidas de calidad.

02 — TÉCNICAS

Técnicas de Aseguramiento de la Calidad

¿Qué es el aseguramiento de la Calidad?

El Aseguramiento de la Calidad del Software (SQA) comprende las actividades destinadas a garantizar que tanto el proceso como el producto cumplan determinados criterios de calidad.

La idea no es esperar hasta el final para descubrir errores.

Técnicas de prueba

Caja Negra

La técnica de Caja Negra permite evaluar el comportamiento del software sin conocer ni analizar cómo está implementado internamente.

El tester se concentra en las entradas que recibe el sistema y en las salidas que produce, verificando que el resultado coincida con lo esperado.

¿Qué se analiza?

  • Entradas y salidas del sistema.
  • Comportamiento de las funciones.
  • Resultados esperados y obtenidos.
  • Casos correctos e incorrectos.

Caja Blanca

La técnica de Caja Blanca analiza la estructura interna del software, teniendo en cuenta cómo está construido y cómo se ejecutan sus instrucciones.

Para realizar este tipo de prueba es necesario conocer el código fuente y su lógica interna. Se busca comprobar que los diferentes caminos y condiciones del programa funcionen correctamente.

Se pueden analizar:

  • Condiciones.
  • Caminos de ejecución.
  • Instrucciones.
  • Bucles.
  • Cobertura de código.

Pruebas funcionales

Pruebas no funcionales
