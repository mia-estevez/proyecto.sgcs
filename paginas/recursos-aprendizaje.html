PREGUNTAS FRECUENTES (FAQ)

En esta sección encontrarás respuestas a las dudas más comunes sobre las metodologías ágiles, la calidad del software y el funcionamiento general de la plataforma.

¿Qué es el modelo en V?

El modelo en V es un modelo de desarrollo de software que relaciona cada etapa del diseño con una fase de prueba. Su objetivo es detectar errores y comprobar que el sistema cumpla con los requisitos establecidos. Se llama así porque sus etapas se representan con forma de V.

¿Cuál es la diferencia entre el modelo iterativo e incremental?

El modelo iterativo permite mejorar una solución mediante ciclos de revisión y ajustes. En cambio, el modelo incremental construye el sistema agregando nuevas partes funcionales. Ambos permiten desarrollar el software de manera progresiva, pero se enfocan en aspectos diferentes.

¿Qué son las metodologías ágiles?

Son formas de organizar el desarrollo de software que priorizan la colaboración, la entrega frecuente de resultados y la adaptación a los cambios. Permiten revisar el progreso durante el proyecto y mejorar el producto según las necesidades del cliente.

¿Qué es Scrum y para qué sirve?

Scrum es un marco de trabajo ágil que organiza las tareas en períodos cortos llamados sprints. El equipo planifica el trabajo, desarrolla una parte del producto y revisa los resultados. Esto facilita la organización y la mejora continua.

¿Qué es Kanban?

Kanban es una metodología visual que permite organizar y seguir el estado de las tareas mediante un tablero. Generalmente, las actividades se distribuyen en columnas como "Pendiente", "En proceso" y "Terminado", lo que ayuda a identificar el avance y los trabajos acumulados.

¿Qué diferencia hay entre Scrum y Kanban?

Scrum organiza el trabajo en sprints con objetivos y revisiones periódicas. Kanban, en cambio, permite gestionar un flujo continuo de tareas mediante un tablero visual. Ambos ayudan a mejorar la organización, pero utilizan formas diferentes de planificar y controlar el trabajo.

¿Qué herramientas se recomiendan para el desarrollo?

Existen herramientas para distintas necesidades. Jira permite organizar proyectos y tareas, GitHub facilita el control de versiones y la colaboración con código, y SonarQube ayuda a analizar la calidad del software. La elección depende de los objetivos y las necesidades de cada equipo.

¿Qué significa calidad del software?

La calidad del software se relaciona con el grado en que un sistema cumple los requisitos y satisface las necesidades de sus usuarios. Se consideran aspectos como la funcionalidad, la seguridad, el rendimiento, la facilidad de uso y la posibilidad de realizar mantenimiento.

Ejercicio 1: Métricas de calidad

Calculá el porcentaje de pruebas exitosas si se ejecutaron 120 casos y 108 fueron correctos.

Enunciado

Se ejecutaron 120 casos de prueba y 108 fueron correctos. ¿Qué porcentaje de pruebas exitosas se obtuvo?

Solución paso a paso

Pruebas exitosas = (Pruebas correctas / Total de pruebas) × 100

108 ÷ 120 × 100 = 90 %
Resultado: 90 % de pruebas exitosas.

Esta métrica permite medir objetivamente el resultado de las pruebas y conocer el estado de la calidad del software.

¿Por qué importa?

Las métricas ayudan a comparar resultados y detectar problemas sin depender solamente de opiniones.

Ejercicio 2: Modelos de desarrollo

Mencioná las principales diferencias entre el modelo en V y el modelo incremental.

Enunciado

Mencioná las principales diferencias entre el modelo en V y el modelo incremental.

Modelo en V

Organiza el desarrollo en etapas relacionadas con pruebas específicas. Cada fase tiene una fase de prueba asociada.

  • Verificación y validación desde temprano.
  • Estructura más rígida.
  • Los cambios pueden ser costosos.

Modelo incremental

Divide el producto en partes o incrementos funcionales. Cada incremento agrega una nueva funcionalidad.

  • Entrega resultados por etapas.
  • Permite recibir feedback.
  • Facilita incorporar mejoras.

Diferencia clave

El modelo en V destaca la correspondencia entre desarrollo y pruebas; el incremental entrega el producto progresivamente.

Ejercicio 3: Buenas prácticas

¿Qué prácticas de aseguramiento de la calidad aplicarías en un proyecto ágil?

Enunciado

¿Qué prácticas de aseguramiento de la calidad aplicarías en un proyecto ágil?

  1. Pruebas continuas: ejecutar pruebas durante el desarrollo y repetirlas después de corregir errores.
  2. TDD: escribir las pruebas antes del código, ejecutarlas y mejorar hasta que pasen.
  3. Revisión de código y Pair Programming: trabajar en conjunto para detectar errores temprano.
  4. Integración continua: integrar cambios con frecuencia y comprobar que el sistema siga funcionando.
  5. Seguimiento de defectos: registrar errores, prioridad, responsable y estado con herramientas como Jira o GitHub Issues.

Pauta de evaluación

La propuesta debe detectar problemas de forma temprana, validar cada cambio y mantener un ciclo de mejora continua: desarrollar, probar, corregir y volver a probar.
