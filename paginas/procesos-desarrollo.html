PROCESOS DEL DESARROLLO DE SOFTWARE

¿Qué es el SDLC?

El SDLC es el conjunto de etapas que se siguen para desarrollar, entregar y mantener un sistema de software.

El ciclo de vida permite organizar el desarrollo y determinar qué se debe hacer, cuándo hacerlo, quién participa, cómo se valida el producto, cómo se controlan los cambios y cómo se mantiene el software.

¿Por qué es importante el SDLC?

El ciclo de vida permite organizar el desarrollo del software y establecer qué hacer, cuándo hacerlo, quién participa, cómo validar el producto y cómo controlar los cambios y mantenerlo.

MODELOS TRADICIONALES

Los modelos tradicionales utilizan procesos de desarrollo más estructurados y planificados. Entre ellos se encuentran Cascada, Modelo en V, Iterativo e Incremental.

Cascada Modelo en V Iterativo Incremental

Modelo en Cascada

¿QUÉ ES?

El modelo Waterfall o Cascada es un modelo lineal y secuencial. Una etapa se completa antes de comenzar la siguiente.

Ventajas

  • Fácil de comprender.
  • Estructura clara.
  • Facilita la documentación.
  • Permite planificar desde el principio.
  • Funciona bien con requisitos estables.

Desventajas

  • Poco flexible.
  • Los cambios pueden ser costosos.
  • Los resultados funcionales llegan tarde.
  • Los problemas pueden descubrirse cuando el desarrollo está avanzado.

¿Cuándo utilizarlo?

Cuando los requisitos están bien definidos, no se esperan grandes cambios y se necesita una planificación estructurada.

Modelo en V

¿QUÉ ES?

El Modelo en V es una evolución del modelo en Cascada que da especial importancia a la verificación y validación. Cada etapa de desarrollo tiene una actividad de prueba asociada.

Ventajas

  • Da mucha importancia a las pruebas.
  • Permite planificar la validación desde el inicio.
  • Facilita detectar errores antes de llegar al producto final.

Desventajas

  • Sigue siendo bastante rígido.
  • Los cambios son costosos.
  • No es ideal si los requisitos cambian constantemente.

¿Cuándo utilizarlo?

Cuando los requisitos están bien definidos y es fundamental verificar y validar cada etapa.

Modelo Iterativo

¿QUÉ ES?

El modelo iterativo desarrolla el software mediante ciclos o iteraciones. En cada ciclo se revisa el resultado para identificar oportunidades de mejora.

Ventajas

  • Permite obtener retroalimentación en cada ciclo.
  • El producto mejora progresivamente.
  • Ayuda a detectar y corregir errores temprano.
  • Se adapta mejor a cambios.

Desventajas

  • Puede requerir mayor planificación y control.
  • Puede aumentar la complejidad de la gestión.
  • Si no se gestiona bien, puede extender el tiempo de desarrollo.

¿Cuándo utilizarlo?

Cuando los requisitos pueden cambiar, se necesita flexibilidad y se desea mejorar el producto de forma progresiva.

Modelo Incremental

¿QUÉ ES?

El modelo incremental divide el producto en partes o incrementos. Cada incremento agrega nuevas funcionalidades y se entrega de forma progresiva.

Ventajas

  • Permite entregar funcionalidades progresivamente.
  • Proporciona valor temprano al usuario.
  • Facilita la adaptación a cambios.
  • Permite priorizar funcionalidades importantes.

Desventajas

  • Requiere una buena planificación de los incrementos.
  • La integración puede presentar problemas.
  • Necesita mantener una arquitectura coherente.

¿Cuándo utilizarlo?

Cuando se necesita entregar valor de manera temprana, los requisitos pueden evolucionar y se busca un desarrollo flexible y progresivo.
